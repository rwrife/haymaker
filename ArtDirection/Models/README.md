# Character model source assets

These eight OBJ files were supplied by the user for character integration. All eight exports have been visually verified in T-pose. They are stored here as art source assets, outside the app's synchronized resource directory.

| File | Character | Vertices | Faces |
| --- | --- | ---: | ---: |
| `mack.obj` | Mack, the player | 11,057 | 21,736 |
| `goldie.obj` | Goldie Voltage | 10,418 | 20,735 |
| `nico.obj` | Nico “Nightshift” Navarro | 10,864 | 21,095 |
| `bruiser.obj` | Bruiser Baxter, the final boss | 10,962 | 21,421 |
| `atlas.obj` | Atlas “Undertow” Reed | 21,000 | 22,375 |
| `duke.obj` | Duke Doubletake | 21,581 | 23,026 |
| `sylvie.obj` | Sylvie “Slipstream” Sloane | 21,038 | 22,438 |
| `cassian.obj` | Cassian “Saint” Sterling | 21,215 | 23,190 |

The files are preserved byte-for-byte from the supplied exports. Their headers identify Blender 5.0.1. Vertex records include RGB colors; there are no external material-library references, UV coordinates, or exported normals. The offline rig builder preserves vertex colors and generates area-weighted smooth normals. OBJ does not carry a skeletal rig or animation, so T-pose alone does not make these assets animation-ready. The runtime exports normalize each sculpt to 2.7 scene units, preserve Y-up/+Z-front orientation, and attach a 16-bone skeleton.

The subsequent exports contain mixed triangle and quad faces. Unlike the initial four triangulated models, these need triangulation if the destination renderer requires triangles.

| Model | Triangles | Quads |
| --- | ---: | ---: |
| Atlas | 3,379 | 18,996 |
| Duke | 3,518 | 19,508 |
| Sylvie | 3,773 | 18,665 |
| Cassian | 4,734 | 18,456 |

See [character backstories](../character-backstories.md) for roles and story direction. The bundled `.fighter` meshes in `Haymaker/Models` are generated by `python3 scripts/rig_fighters.py`. Mack and Bruiser replace the prototype fighters in the current bout; the other six rigs are ready for future roster integration. Vera Velvet is still missing a source model.

Each rig includes hips/spine/neck/head, shoulders/elbows/hands and hips/knees/feet. Skin weights isolate the jaw from the body and arms; only the lower neck blends. Head yaw is limited to three degrees, with recoil applied to the torso. A two-bone arm solver preserves limb lengths during guard, telegraph, jab, hook, and uppercut poses. The binary `HMR1` layout is little endian: a 16-byte header (magic, vertex count, index count, bone count), 16-byte bone records (signed parent index and global bind XYZ), 60-byte vertices (position/normal/RGB, four float weights and four UInt16 bone indices), then UInt32 triangle indices. Source OBJs are unchanged.

Validate deterministic exports, indices, normals, normalized weights and face isolation with `python3 scripts/test_rig_fighters.py`. On macOS with Xcode, `bash scripts/verify_fighter_rigs.sh` exercises 216 combat pose combinations per model through the actual SceneKit loader and renders `/tmp/haymaker-rig-guard.png`. Joint placement and skin weights are procedural and may benefit from hand-painted refinements for future extreme animations; current poses deliberately avoid extreme neck movement.
